FAQ

How does login work? (Google OAuth setup)

This admin panel uses Google OAuth. Only accounts on an allow-listed domain can sign in.

Server env vars:

GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxxxx
SESSION_SECRET=<random 32+ char string>
ADMIN_ALLOWED_DOMAINS=ramosjames.com    # comma-separated for multiple
PUBLIC_URL=https://your-host.com         # used to build the OAuth redirect URI

Google Cloud Console setup:

  • Create an OAuth 2.0 Client ID (Web application) at console.cloud.google.com → APIs & Services → Credentials.
  • Add https://your-host.com/admin/auth/callback as an Authorized redirect URI (replace your-host.com with the actual host).
  • Copy the Client ID and Client Secret into the env vars above.

Sessions are signed HMAC-SHA256 cookies with a 12-hour lifetime. If SESSION_SECRET is not set, the server generates a random one at startup and everyone is logged out on restart.

What environment variables do I need to set for a new firm?

Secrets are per-firm and named FIRM_<UPPERCASE_ID>_<VAR>. For a firm with id smithlaw, set:

FIRM_SMITHLAW_QUO_API_KEY=...
FIRM_SMITHLAW_SLACK_BOT_TOKEN=xoxb-...
FIRM_SMITHLAW_SLACK_TEXT_MESSAGES_WEBHOOK_URL=https://hooks.slack.com/...
FIRM_SMITHLAW_SLACK_MISSED_CALLS_WEBHOOK_URL=https://hooks.slack.com/...
FIRM_SMITHLAW_SLACK_HUMAN_CALLS_WEBHOOK_URL=https://hooks.slack.com/...
FIRM_SMITHLAW_SLACK_SONA_CALLS_WEBHOOK_URL=https://hooks.slack.com/...
FIRM_SMITHLAW_SLACK_LEAD_CALLS_WEBHOOK_URL=https://hooks.slack.com/...
FIRM_SMITHLAW_SLACK_LEGAL_ASSISTANT_WEBHOOK_URL=https://hooks.slack.com/...
FIRM_SMITHLAW_SLACK_LEAD_CALLS_CHANNEL_ID=C0000000000
FIRM_SMITHLAW_SLACK_LEGAL_ASSISTANT_CHANNEL_ID=C0000000000

ANTHROPIC_API_KEY is shared across all firms (used only for lead classification), no per-firm version is needed.

What webhook URLs do I give Quo?

In Quo's webhook settings, point each event to the URL matching the firm's ID:

Messages:     https://<your-host>/webhooks/quo/<firmId>/messages
Calls:        https://<your-host>/webhooks/quo/<firmId>/calls
Call summary: https://<your-host>/webhooks/quo/<firmId>/call-summary

Each registered firm's exact URLs are shown in the firm card above once loaded.

Where do the Slack bot token and webhook URLs come from?
  • Bot token: create a Slack app in the firm's workspace, add scopes (chat:write, channels:read, groups:read, channels:history, groups:history, channels:join, users:read), install to workspace, then copy the "Bot User OAuth Token" (starts with xoxb-).
  • Incoming webhook URLs: in the same app, add "Incoming Webhooks" and create one per channel (missed-calls, sona-calls, human-calls, lead-calls, legalassistant-phone, text-messages).
  • Channel IDs: in Slack, right-click the channel → View channel details → scroll to bottom, or open the channel in browser and grab the ID from the URL.
The channel-topic tagging isn't working for a firm. Why?

The bot reads @mentions live from each case-channel's topic (via conversations.info) every time it posts. If mentions aren't showing up:

  • Confirm the bot is in the case channel (it auto-joins on first post — check it wasn't kicked).
  • Confirm the channel topic contains actual Slack mentions like <@U12345>, not just @Name text.
  • Confirm the bot has channels:read/groups:read scope.
What does the fallback call-check do?

Quo occasionally never sends call.completed or /call-summary events, which would otherwise leave the call silent in Slack. On the ringing event, the router schedules a check 185s later. Before acting, it queries GET /v1/calls/{callId} to get the real status, then routes based on what actually happened (missed / menu-hangup / answered by Sona / answered by human). Each firm has its own set of pending timers.

How is data isolated between firms?

Each firm has its own contacts cache, users cache, Slack channel cache, call cache, pending-call-check timers, and resolved-call set. A rate-limit or bug affecting one firm's cache load does not affect another. Secrets (Quo API key, Slack bot token, webhook URLs) come from env vars named FIRM_<ID>_* and are never shared. The only shared piece is ANTHROPIC_API_KEY.

Where are firms stored? (Postgres vs firms.json)

There are two sources, loaded in this order at startup:

  • firms.json (committed to git) — holds the default firm (ramosjames). This never changes and always loads first, so the original firm keeps working regardless of the database.
  • Postgres — holds firms added through this admin UI. Loaded after firms.json. Requires DATABASE_URL to be set.

When you add a firm here and DATABASE_URL is set, it's written to the firms table and survives redeploys automatically. If DATABASE_URL is not set, the firm is written to firms.json on disk instead — which is ephemeral on most hosts, so you'd need to commit it to git (the success screen gives you the blob).

How do I set up the Postgres database?

Provision a Postgres instance (Fly Postgres, Render, Neon, Supabase, etc.) and set its connection string as an env var:

DATABASE_URL=postgres://user:pass@host:5432/dbname
DATABASE_SSL=                 # leave unset for managed DBs (SSL on by default)
                              # set DATABASE_SSL=disable for a local/no-SSL DB

The router creates the firms table automatically on first boot (CREATE TABLE IF NOT EXISTS) — no migration step needed. Secrets (Quo API key, Slack tokens, webhook URLs) are never stored in the database; they always come from FIRM_<ID>_* env vars.

How do I edit or remove a firm?

This UI only adds firms. To edit or remove a Postgres-stored firm, update or delete its row in the firms table (then redeploy or restart to reload). For the default firm in firms.json, edit the file in the repo and redeploy. Either way, also remove the corresponding FIRM_<ID>_* env vars when decommissioning a firm.

Legacy Quo webhook URLs (without /<firmId>/) — still supported?

Yes. The old routes /webhooks/quo/{messages,calls,call-summary} route to DEFAULT_FIRM_ID (default: ramosjames). You can migrate URL by URL at your own pace, or leave the default firm on the legacy URLs and only use per-firm URLs for new firms.
